# PRD — NeumoAI-D (Napas Anak Indonesia) v2 — Flutter

Tanggal: 2026-08-05
Status: Disetujui untuk migrasi (Parents scope)

## 1. Ringkasan Produk

NeumoAI-D adalah platform skrining dini pneumonia pada anak melalui analisis AI suara batuk. Dibangun untuk orang tua, pengasuh, dan kader Posyandu sebagai deteksi awal pneumonia sebelum pemeriksaan lanjutan di fasilitas kesehatan.

**v2 = migrasi penuh dari React/Vite (web) ke Flutter (Android)** dengan arsitektur offline-first dan struktur yang siap disambungkan ke backend & AI asli.

## 2. Visi & Nilai

- Deteksi dini pneumonia lebih cepat dan terjangkau, tanpa harus ke rumah sakit lebih dulu.
- Pemantauan kesehatan anak (pertumbuhan, vaksinasi, riwayat skrining) dalam satu tempat.
- **Offline-first:** aplikasi tetap berfungsi penuh tanpa internet; data tersinkronisasi otomatis saat koneksi kembali.
- AI adalah alat bantu skrining, bukan pengganti diagnosis medis profesional (disclaimer eksplisit).

## 3. Target Pengguna

| Persona | Platform | Fungsi utama |
|---|---|---|
| **Parents** (orang tua / pengasuh / kader Posyandu) | **Flutter — Android** | Skrining batuk anak, riwayat pemeriksaan, kelola profil anak |
| Dokter | Web (proyek terpisah, future) | Tinjau kasus, catat keputusan |
| Admin | Web (proyek terpisah, future) | Kelola akun, data riset, dashboard sistem |

> **Keputusan scope:** migrasi Flutter ini **hanya untuk Parents**. Dokter & Admin adalah aplikasi Web terpisah di luar lingkup. Dengan demikian Flutter ini tidak memiliki role-based access control.

## 4. Lingkup Migrasi

### In scope
- Migrasi penuh semua **19 layar** versi React yang berorientasi Parents.
- Target: **Android**.
- Data **mock** untuk sementara, dengan **fondasi offline-first dan struktur siap-API**.
- Tema Material Design 3, mode terang/gelap, font Inter.

### Out of scope (fase ini)
- Backend/API asli (Auth server, AI screening, push notification).
- Role-based access / dashboard admin / fitur dokter.
- Platform lain (iOS, Web, Desktop).
- i18n (konten Bahasa Indonesia saja).
- Rekaman audio asli (tetap simulasi 5 detik seperti sekarang).
- Notifikasi push (daftar notifikasi tetap ada, tapi dari data lokal).

## 5. Kebutuhan Fungsional

### 5.1 Auth & Onboarding
- Splash → onboarding → login/register/forgot.
- Login email & Google (simulasi/mock).
- Profil orang tua: nama, email, telepon, emoji, peran.

### 5.2 Beranda (Home)
- Sapaan berdasarkan waktu (pagi/siang/sore/malam) + nama pengguna.
- Child selector multi-anak (horizontal, tambah anak).
- Kartu status kesehatan: ring keyakinan AI, label risiko, deskripsi, tanggal skrining terakhir.
- Quick actions: Mulai Skrining, Riwayat Kesehatan, Edukasi Napas, Faskes Terdekat.
- Rekomendasi AI terbaru.
- Daftar fasilitas kesehatan terdekat (buka/tutup, jarak, rating).
- Status sinkronisasi + banner offline.

### 5.3 Kelola Anak
- Daftar anak.
- Form tambah/edit: nama, gender, tanggal lahir, berat lahir, berat, tinggi, emoji, riwayat medis, vaksinasi.
- Hapus anak.
- Anak aktif tersimpan dan dipakai di seluruh alur.

### 5.4 Skrining (alur inti)
- **Langkah 1 — Gejala:** pilih gejala, durasi batuk, pola pernapasan.
- **Langkah 2 — Rekam:** simulasi rekaman 5 detik, waveform animasi, indikator kebisingan, opsi ulangi, status "tersimpan lokal".
- **Langkah 3 — Proses:** animasi AI, daftar tahapan (upload → ekstraksi → model → laporan), lalu otomatis pindah ke hasil.

### 5.5 Hasil Skrining
- Tingkat risiko (rendah/sedang/tinggi), keyakinan AI.
- Explainable AI: spektrogram, Grad-CAM, kontribusi SHAP.
- Rekomendasi dokter / faskes.
- Aksi lanjut (lihat riwayat, skrining ulang, dll).

### 5.6 Riwayat
- Daftar skrining per anak.
- Grafik pertumbuhan (berat/tinggi).
- Kalender & detail skrining.

### 5.7 Edukasi & Notifikasi
- Daftar artikel + halaman artikel.
- Notifikasi per tipe (vaksinasi/reminder/ai/medical), read/unread, badge di beranda.

### 5.8 Profil & Pengaturan
- Profil, edit profil, privasi, pengaturan (tema gelap/terang).

### 5.9 Offline-first
- Hasil skrining tersimpan lokal (Drift/SQLite).
- Status sinkronisasi per item: pending / synced / failed.
- Antrean sinkronisasi generik + retry otomatis saat koneksi kembali.
- Banner & indikator status sinkronisasi di UI.

## 6. Kebutuhan Non-Fungsional

- **Platform:** Android; Material Design 3; mode terang/gelap; font Inter.
- **Kinerja:** responsif di layar mobile; animasi halus (fade-up, pulse-ring, wave-bar, float).
- **Keandalan:** offline-first penuh; tidak error saat offline; tidak ada kehilangan data.
- **Keamanan:** tanpa secret/hardcoded credential; disclaimer medis eksplisit.
- **Skalabilitas arsitektur:** repository layer swap `Mock → Api` tanpa mengubah UI.
- **Testabilitas:** model, repository, `SyncQueue`, dan layar inti memiliki test.

## 7. Model Data Utama

- `Child` (+ `Vaccination`), `Screening`, `Profile`, `Article`, `AppNotification`, `HealthCenter`, `GrowthRecord`.
- Enum: `RiskLevel (low | medium | high)`; `SyncStatus (pending | synced | failed)`.

## 8. Kriteria Keberhasilan

1. Semua 19 layar berfungsi setara dengan versi React.
2. Berjalan sebagai aplikasi Android (bukan web preview).
3. Offline-first: skrining tetap bisa dibuat tanpa internet, lalu sinkronisasi otomatis saat online.
4. Struktur siap disambung ke API & AI tanpa mengubah UI.

## 9. Catatan

- Rekaman audio bersifat simulasi; siap ditambah rekaman asli (paket `record` + `permission_handler`).
- Detail teknis (Riverpod, Drift, go_router, struktur folder, peta layar) ada di dokumen desain: `2026-08-05-flutter-migrasi-design.md`.
